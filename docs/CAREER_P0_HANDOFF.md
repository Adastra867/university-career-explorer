产品要求：少填、少重复、先看到有用结果；资料来源清楚；用户知道哪些内容会提交给管理员。

## 3. 学生端体验

### 3.1 入口

首页主问题：**你现在最想解决哪件事？**

| 任务标识 | 展示文案 | 初始输入提示 | 首轮结果 |
|---|---|---|---|
| `explore_direction` | 我还不知道以后做什么 | 说说专业或接触过的领域，以及当前困惑 | 2—3 个探索方向、推荐依据、一项探索动作 |
| `build_experience` | 我想知道现在可以做什么 | 说说当前阶段和做过的事，没有经历也可以 | 整理已有经历，或给一个适合当前阶段的小任务 |
| `find_opportunity` | 我想找实习或工作 | 粘贴简历、经历或目标岗位；JD 可选 | 接入现有岗位/JD 分析，给出优先处理事项 |
| `compare_options` | 我在几个选择之间犹豫 | 写下正在比较的选项，最在意的条件可选 | 按共同维度比较、列出关键未知项和核实动作 |

年级用于调整默认建议，不作为限制入口的规则。首次体验不强制填写姓名、学号、电话、微信、学校排名或完整职业目标。

### 3.2 输入与资料导入

每次保持一个清晰的主要输入区，支持：

1. 一句话或一段自由文本。
2. 粘贴简历、项目经历、个人介绍。
3. 直接使用网站已保存的资料。
4. 沿用已经验证可用的文件解析能力。

P0 必须保证文本粘贴路径可靠。若项目没有文件解析，先完成文本路径；新增文件解析不是本轮阻塞项。已有的文件解析功能应接入统一画像，不能丢失。

输入区应提供简短示例和“没有也可以”的提示。没有简历不能阻止低年级学生继续。

首次上传到服务端、调用在线模型之前，展示简洁说明：资料用于什么、是否调用在线 AI、个人进度如何保存、管理员在什么情况下能看到记录。按既定产品告知流程记录相应操作。不要等结果生成后才告知材料已发送给在线 AI。

### 3.3 关键追问

由服务端执行以下规则，不能只靠系统提示词：

- 一个任务最多发出两次关键追问，每次只有一个主要问题。
- 从当前输入或有效画像中已得到的信息，不重复问。
- 每个问题都有“不确定／先跳过”，并提供“直接给我建议”。
- 跳过后记录在当前任务的 `skipped_fields` 中，不换一种措辞重问。
- 点击“先跳过”或“直接给我建议”后进入初步结果，不自动追问其他资料。
- 达到两次上限后进入结果。未知字段保留未知，不用“资料不完整”挡住流程。
- 刷新、网络重试或重复点击不重置计数。
- 只有用户明确开始另一项任务时才建立新的追问预算；AI 无权自行新建任务绕过上限。
- 结果生成之后的补充，由用户主动点击“补充信息／重新分析”触发。

每个问题须有稳定的 `question_id`、目标字段和提问理由。相同请求重试返回原问题，不重复生成或计数。每轮返回可用的阶段性内容，避免只有一个漫长的“正在思考”。

### 3.4 初步结果与资料确认

结果页先展示本次任务的有效内容，再展示简短资料卡。资料卡优先显示约 3—5 个关键项，其余可展开编辑。

示例：

> 本次用于建议的信息：大二｜能源相关专业｜做过太阳能电池实验｜暑假可投入两个月  
> 正在比较：储能、光伏  
> 操作：信息正确／修改一项／暂不确认

“信息正确”只确认卡片实际展示的字段。后端接收明确的字段路径、值和版本，不把整份 AI 报告或隐藏字段一起确认。

确认画像不是查看结果的前置条件。用户主动修正字段后应立即更新相关资料；受影响的旧结果标注“使用此前资料生成，可重新分析”。

页面须区分“AI 建议”“材料中明确提及的信息”“待确认整理”。用户确认表示认可其填写或整理内容，不表示经过外部真实性核验。

### 3.5 两个完成动作

- **保存我的进度**：保存个人草稿，便于同一浏览器继续。
- **预览并提交给管理员**：展示本次实际共享内容和接收方，随后明确提交。

如果已自动保存，可将第一个动作改为保存状态和“继续其他任务”。“保存”不隐含管理员提交。

没有活动来源的普通访问也可以使用工具和保存进度。不要自行把普通访问归入某个班级；提交前应有明确可见的收集活动或接收方。

## 4. 统一画像与来源

### 4.1 公共资料与当前任务分开

公共资料包括教育背景、专业、已提供的经历、技能自述、已明确的长期偏好。

当前任务包括“这次想解决什么”、这次比较的选项、这次使用的 JD、当前城市/时间条件、追问状态和结果。临时比较某方向不能自动覆盖长期目标。

建议提供统一的资料读取与更新服务。现有页面通过适配层读取，逐步清除各页面自行维护不同画像副本的做法。

### 4.2 字段结构

以下为语义示例，可按实际语言实现为类型或 JSON Schema。技能、经历等数组应保留条目级来源。

```json
{
  "schema_version": 1,
  "profile_revision": 3,
  "fields": {
    "education.stage": {
      "value": "大二",
      "value_state": "known",
      "source_type": "user_text",
      "source_refs": [
        {"source_id": "message_example_1", "quote": "我大二"}
      ],
      "confirmation_state": "unconfirmed",
      "updated_at": "2026-11-04T10:00:00Z"
    },
    "education.major": {
      "value": "能源相关专业",
      "value_state": "known",
      "source_type": "user_text",
      "source_refs": [
        {"source_id": "message_example_1", "quote": "能源专业"}
      ],
      "confirmation_state": "unconfirmed",
      "updated_at": "2026-11-04T10:00:00Z"
    },
    "preferences.city": {
      "value": null,
      "value_state": "unknown",
      "source_type": null,
      "source_refs": [],
      "confirmation_state": "unconfirmed",
      "updated_at": "2026-11-04T10:00:00Z"
    }
  }
}
```

推荐枚举：

- `value_state`：`known | unknown | not_applicable`。跳过状态存于当前任务，不应清空全局已有资料。
- `source_type`：`user_form | user_text | document_extract | legacy_import | ai_inference`。
- `confirmation_state`：`unconfirmed | confirmed | corrected`。

`source_type` 与 `confirmation_state` 独立。确认后保留原来源；纠正时保留本次修改和必要的原始来源关系，不把历史导入或模型推断改写成原始手填事实。

### 4.3 必须保持的语义

1. **未提及、跳过、明确没有，含义不同。** “尚未提供实习经历”不等于“没有实习经历”。
2. “会一点 Python”只能保存为相应技能自述，不自动升级成熟练或精通。
3. “做过实验”不能自动扩展为独立完成项目、发表论文、获得奖项或量化成果。
4. AI 的推断默认保存在候选建议中，不写入已确认事实，不用于学历、地区等硬性筛选。
5. 用户明确接受某项偏好建议后，可以进入其已确认偏好；仍保留 AI 来源。接受一条路线不等于确认自己具备路线要求的全部能力。
6. 简历中的学校不能自动变成能力分；写作风格不能直接生成人格或软实力等级。
7. 浏览某岗位只记录为浏览；只有明确“设为目标”才更新目标。
8. 不生成缺少校准依据的“画像置信度 92%”等数字。
9. 如果保留正式量表，按其既有规则评分；AI 不代答，不把缩短或改写的量表沿用为原分数。

### 4.4 旧本地资料迁移

- 盘点并列出明确的旧 `localStorage` 键名白名单。
- 发现旧资料时显示导入预览，用户主动导入后才上传云端。
- 只导入原始答案、教育背景、经历、有效目标等允许字段；不上传整个浏览器存储。
- 旧匹配分、随机补分、旧版推断、API Key、管理状态不导入事实画像。
- 标记 `legacy_import`，保留导入时间和来源版本。
- 与已有云资料冲突时展示差异或保留新值，不静默覆盖。
- 相同导入重复执行不能重复追加经历。
- 用户拒绝导入后仍能继续使用；本轮不破坏现有本地数据。

## 5. AI 接入与输出契约

### 5.1 实现方式

优先复用现有后端和模型客户端，新增统一的 intake 服务，负责资料提取、阶段性建议和必要追问。模型提供商、模型名、超时和调用额度通过服务端配置管理。

如果项目当前为纯静态页面，增加最小的同仓后端 API 和持久数据库；前端调用同源接口。不要为了本轮迁移整个框架，不需要多 Agent、向量数据库或消息总线。

模型密钥放在服务端环境变量中，不出现在 HTML、前端 JS、浏览器存储、响应体或日志中。

每轮只提供当前任务所需的资料与必要上下文。与建议无关的联系电话、证件号等不需要进入模型上下文。

保存草稿与调用模型分开。只有用户点击生成、提交追问答案或主动重新分析时调用模型；输入防抖保存、页面刷新、读取历史记录和管理员查看均不触发新的模型调用。

### 5.2 模型必须返回可验证的结构

下列为应用内部约定示例，不是任何供应商的原生 API 格式。模型响应由服务端校验后才能用于更新页面或资料。

```json
{
  "schema_version": 1,
  "profile_patch": [
    {
      "field_path": "education.stage",
      "value": "大二",
      "claim_type": "explicit",
      "source_id": "message_example_1",
      "evidence_quote": "我大二"
    }
  ],
  "result": {
    "summary": "可以先比较两个方向的日常工作，再选择一次短期体验。",
    "options": [
      {
        "title": "光伏相关岗位探索",
        "reason": "你提到做过太阳能电池实验，可从已有接触切入。",
        "source_refs": ["message_example_1"],
        "unknowns": ["实验中个人负责的具体工作尚未提供"],
        "next_action": "查看一份相关岗位描述，标记自己做过或希望体验的任务。"
      }
    ]
  },
  "next_question": {
    "field_path": "experience.personal_action",
    "question": "那次实验中，你自己主要负责什么？",
    "reason": "用于区分已有经历中的具体能力证据。",
    "options": ["搭建或操作", "数据处理", "结果分析", "还不确定"],
    "allow_skip": true
  }
}
```

`next_question` 允许为 `null`。`question_id`、追问计数、任务 ID、用户 ID、确认状态和提交状态由服务端控制；不信任模型生成这些权限或流程字段。

### 5.3 校验与应用规则

- 为输出定义 Schema；校验字段路径、类型、枚举、长度和数组数量。
- `profile_patch` 只能操作明确允许的画像字段。
- 来源 ID 必须属于当前授权任务或已授权资料；证据原文须能在对应材料中定位。
- 没有来源支持的内容只能作为建议或推断，不能作为明确事实补进画像。
- 模型返回“已确认”“管理员”等内容不能改变真实确认状态或权限。
- 新提取事实先形成待确认候选；不覆盖用户已经明确修正的内容。冲突时显示简短差异。
- 对当前任务而言，用户原话中已明确提供的内容可用于初步建议；含糊或推断内容不能形成硬性结论。
- 追问是否发出由服务端按预算、已知字段和跳过集合再次判断。
- 用户输入、简历、JD 中的指令都作为待分析数据，不能修改系统规则或触发外部操作。
- 前端按普通文本或经过清理的 Markdown 渲染，防止原始 HTML/脚本执行。

### 5.4 异常和降级

- 超时、网络错误、限流、空响应、无效 JSON 均有明确错误类型和可读提示。
- 无效结构最多执行一次受时间预算约束的修复重试；失败后保留输入并允许重试。
- 没有模型配置时，允许使用既有规则能力和手动资料输入，标明当前能力；不能用演示数据冒充在线 AI 结果。
- 没有招聘搜索结果时，继续使用已有个性化检索方案和招聘入口；不要生成虚构在招岗位、企业链接、截止日期。
- AI 完整功能未实测通过时，在交付中列出具体未验证项，不能以降级路径代替“AI 已接通”的验收。

## 6. 保存、版本和提交一致性

### 6.1 最小数据对象

以下为逻辑对象，按当前技术栈选择表或 JSON 文档，不要求为每个字段、推断、消息另建表。

| 对象 | 最少内容 |
|---|---|
| `guest_sessions` 或现有身份系统 | 访客身份、服务端会话凭证哈希、过期时间 |
| `profiles` | 所有者、统一画像、字段来源与确认状态、资料版本 |
| `intakes` | 所有者、任务类型、活动、输入/来源、追问状态、输入版本、结果及其依赖版本 |
| `campaigns` | 活动名称、公开 slug、管理员归属、开放状态、展示说明、提交范围 |
| `submissions` | 所有者、活动、提交快照、提交时间、状态、幂等键、告知版本 |

管理员认证可复用既有系统；没有时增加必要的账号和会话存储。画像、任务、提交都必须有服务端所有者关联。

### 6.2 个人草稿

输入后进行适当防抖的自动保存。显示“正在保存／已保存／保存失败”；只有服务器确认才能显示“已保存”。

个人草稿供本人继续使用。管理员业务接口不返回未提交草稿、私人材料或完整未提交聊天。

保存失败时保留当前输入。不要将未写入数据库的内容显示为可跨刷新恢复；可用短期本地缓存提示“仅保存在此设备”，并在恢复连接后重试。

### 6.3 资料与结果版本

每个任务维护 `input_revision`，模型分析记录 `based_on_input_revision` 和实际使用的输入摘要或内容指纹。

- 用户补充、纠正会影响分析的事实或条件时递增输入版本。
- AI 提取结果写回、保存状态变化、结果写回、追问计数变化，不应自动递增分析输入版本。
- 仅确认相同值而不改变分析依据时，可以只更新确认元数据。若实际使用值或分析条件改变，必须使结果过期。
- 公共画像变化时，比较当前任务实际依赖的内容；有影响才更新该任务的输入版本。
- 模型返回时若版本已经变化，保留为旧结果或丢弃，不覆盖当前结果。
- 不允许把新资料和基于旧资料生成的结果拼成一份当前报告。

资料更新应带预期版本，处理多标签页或并发修改。冲突时提示重新加载或合并，不能静默覆盖。

### 6.4 提交预览与快照

提交前服务端根据当前授权任务生成预览，至少包含：

- 接收活动及其管理员/组织者展示名称。
- 本次相关的个人字段与确认状态。
- 本次任务中实际将共享的输入或材料片段。
- 本次结果、实际使用的输入版本、结果生成模式。
- 提交范围说明、告知版本。

默认共享当前任务所需内容，不带入其他私人任务、无关聊天或未经预览的整个简历附件。P0 不必制作复杂的逐字段权限编辑器，但页面预览必须与实际提交范围一致。

可用短期服务端预览记录或签名版本标识实现。提交时核对预览、输入和结果版本；发生变化应返回冲突并让用户重新预览。服务端从已授权数据生成快照，不信任前端上传的所有者、确认状态或整份画像对象。

预览标识必须绑定完整共享载荷，包括字段值、来源、确认状态、材料片段、结果、接收活动和共享范围。可保存不可变预览载荷，或对完整载荷计算签名摘要；不能只绑定 `input_revision`。首次提交时核对完整载荷是否仍与预览一致；元数据发生变化也应重新预览，不能无提示替换成最新内容。

成功后保存不可随个人资料编辑而变化的快照，包含 `input_revision`、生成模式、规则/模型与提示词版本等必要追溯信息。后续改资料不会覆盖旧提交。

学生再次主动提交更新版本时，生成明确的新版本并关联之前的提交；普通网络重试不能产生新版本。后台默认可展示最新版本，保留查看历史版本的方式。

同一访客、同一任务、同一活动中的多次提交关联为同一共享链。撤回作用于这条链的全部历史版本。撤回后再次明确提交属于新的共享授权，仅新提交可见，不自动恢复以前已撤回的版本。

### 6.5 幂等和事务

- 每次明确提交生成一个 `idempotency_key`，该次动作的重试始终复用。
- 数据库对“所有者 + 幂等键”建立唯一约束。
- 同键同内容返回同一记录；同键不同内容返回冲突。
- 验证身份与归属后先查幂等键：已成功且请求指纹相同的重试，返回原提交 ID、回执和当前状态，不重新执行创建新提交时的活动开放、预览有效期和最新版本检查。这样响应丢失后，即使活动关闭或草稿已变化，也能取回真实回执。
- 已撤回记录的幂等重试只返回其撤回状态，不恢复共享；已删除且身份失效时不得以旧幂等键重新创建内容。
- 新幂等键创建记录时，在同一事务中完成权限、活动状态、版本校验与快照插入。
- 请求超时、双击、刷新重试都不能制造重复记录。
- 如果自动保存仍在进行，提交应先完成同步或返回可恢复提示，不能默认草稿已持久化。

## 7. 活动链接、访客身份和管理员后台

### 7.1 分享活动

管理员能创建、查看和关闭活动，至少设置名称、简短说明、提交范围。生成可复制的公开入口链接与二维码。

可采用 `/start?campaign=<slug>`，沿用现有路由更合适时可调整。URL 中不要带学生个人资料或访问凭证。

公开活动接口只返回活动展示配置。活动链接用于进入和识别来源，没有读取任何学生记录的权限。

活动关闭后，阻止新提交并给出清楚提示；学生自己的既有进度仍按其权限可读，不丢失输入。管理员已有记录继续按权限和保存期限管理。

### 7.2 访客访问

P0 支持无需注册的访客体验和同一浏览器继续。优先复用已有认证；没有时由服务端签发随机、不透明会话凭证，使用安全 Cookie，并在服务端存储凭证哈希与过期时间。

生产环境 Cookie 使用 `HttpOnly`、`Secure` 和适当的 `SameSite` 配置。所有写接口执行适当的来源/CSRF 校验；公开模型接口和登录接口限流。

用户 ID、画像 ID、活动 slug、提交 ID 都不是访问凭证。服务端必须根据会话确定所有者，拒绝跨用户读取、修改、提交或删除。

本轮不要求新建完整学生账号体系。如果已有账号可沿用；否则明确同一浏览器续用的范围，不承诺清除 Cookie 或换设备后仍能恢复，也不用设备指纹识别人。

### 7.3 管理员认证

复用现有可靠认证。若没有，P0 可以配置一个管理员账号，使用服务端密码哈希、独立登录会话、登录限流和退出失效。

禁止默认通用密码、前端写死口令、通过 URL 参数提升角色或仅靠隐藏页面限制访问。数据库和模型的服务端密钥不下发浏览器。

管理员查询按活动归属过滤。单管理员只需管理本实例分配给自己的活动；不要为 P0 扩展学校、企业、辅导员多层复杂角色体系。

### 7.4 管理员记录列表与详情

列表支持分页，按活动、任务类型、年级、专业、提交时间筛选。至少展示：

- 用户/访客编号，不称为已匿名化身份。
- 活动名称、任务类型、年级和专业（允许未知）。
- 本次目标或困惑摘要。
- 提交时间、提交版本和状态。
- 关键资料确认情况。

详情查看本次提交快照中的用户输入、字段及其来源/确认状态、分析结果、生成模式和时间。原始输入与 AI 归纳分区展示。

后台只对已提交且仍可见的记录返回内容。未提交草稿不能通过详情接口、搜索接口、关联查询或旧地址泄露。

如果展示统计，区分“用户明确回答”“用户确认的 AI 整理”“尚未确认的推断”。未确认推断不计为学生真实意向；AI 推荐的岗位不能计为学生选择的岗位。统计未知项时保留未知分组，不当作否定答案。

P0 不要求复杂图表、批量评语、自动消息或批量导出；先完成可用的列表和详情。

### 7.5 撤回、删除和保存期限

学生能查看自己的提交并撤回共享。撤回后管理员列表和旧详情地址都不能再访问正文；个人草稿可继续保留。管理员只可看到必要的“已撤回”状态，不能据此恢复正文。

撤回覆盖该共享链的全部历史版本。列表不能自动回退到旧版本，历史详情与关联查询同步失效；新一轮明确提交也不能重新开放已撤回的历史内容。

提供删除本人云端资料的操作，清理关联画像、任务与提交正文，失效相应会话，并清除会导致重新上传的本地缓存。删除和正在进行的保存/AI 写回应做并发保护，避免晚到请求重新创建数据。

处理说明中写明保存期限和删除方式，保存期限由项目配置并落实清理机制。不要把会话过期当成数据已经删除。日志不保留用于绕过撤回或删除的完整输入、副本和秘密。

## 8. 统一岗位匹配

### 8.1 复用同一实现

核对首页、独立岗位搜索页、JD 分析与综合报告的计算逻辑。抽出一套公共的规范化输入、评分与解释实现；旧入口调用同一实现或跳转到新入口，避免长期维护两套规则。

评分修复属于 P0。需要删除业务上的随机补分和无依据补分。

### 8.2 评分契约

- 对相同规范化画像、相同规范化 JD、相同规则版本，返回相同分数和分项。
- 模型可辅助提取 JD 要求或生成说明；不要让不可控的随机补分替代计算规则。
- 如果原始文本由模型抽取为结构化要求，记录抽取版本并适当按内容缓存。确定性验收使用固定规范化输入。
- 明确哪些要求有材料支持、哪些材料尚未体现、哪些信息不足。
- 材料不足或无法形成有效分母时，返回 `not_evaluated` 或等价状态，分数为 `null`，不得自动给一个“看起来合理”的分数。
- “材料未体现”不能自动写成“学生没有该能力”。
- 硬性门槛、能力证据、关键词覆盖分开解释；未确认推断不能用作硬筛选事实。
- 继续说明匹配分表达材料与 JD 的对应程度，不代表录用概率。

优先复用经核查合理的首页规则，并明确规则版本。无需为这次改造新建复杂权重模型。

### 8.3 招聘信息

真实岗位保留原文链接、来源和已有可核验的发布时间/查询时间。搜索失败时提供检索方案和招聘入口，并在类型和 UI 上明确与真实在招岗位的区别。

当前任务的探索方向可以是 AI 建议；具体企业是否在招、截止日期和申请条件必须来自可核验材料，不能由模型补全。

## 9. 建议接口

以下路径是接口职责示例，按现有项目调整。优先复用已有端点；每个端点必须在服务端做身份、范围、字段白名单与输入校验。

| 接口 | 职责与关键约束 |
|---|---|
| `POST /api/guest-session` | 建立或恢复本人访客会话；不接受客户端指定其他所有者 |
| `GET /api/campaigns/:slug/public` | 只返回公开活动配置 |
| `GET /api/me/profile` | 读取本人统一画像 |
| `PATCH /api/me/profile` | 更新或确认白名单字段；校验预期版本 |
| `POST /api/me/profile/import` | 用户确认后导入白名单旧资料；幂等、处理冲突 |
| `POST /api/intakes` | 用户主动创建当前任务，绑定合法活动 |
| `GET /api/intakes/:id` | 读取本人草稿、结果与保存状态 |
| `PATCH /api/intakes/:id/draft` | 防抖保存本人输入与允许编辑的条件，校验预期版本；不调用模型、不修改追问预算 |
| `POST /api/intakes/:id/turns` | 输入、回答、跳过或直接看建议；幂等并控制追问预算 |
| `POST /api/intakes/:id/submission-preview` | 从授权草稿生成本次共享预览及版本标识 |
| `POST /api/submissions` | 核验预览、活动、版本并在事务中保存快照；使用幂等键 |
| `GET /api/me/submissions` | 查看自己的提交及回执 |
| `POST /api/me/submissions/:id/withdraw` | 撤回本人提交；管理员正文访问同步失效 |
| `DELETE /api/me/data` | 删除本人相关云数据；使会话失效并阻止旧请求回写 |
| `POST /api/admin/login`、`POST /api/admin/logout` | 管理员登录与退出；服务端验证 |
| `GET/POST /api/admin/campaigns` | 列出和创建本人管理的活动 |
| `PATCH /api/admin/campaigns/:id` | 更新活动说明、开放状态等允许配置 |
| `GET /api/admin/submissions` | 已授权、已提交记录的分页和筛选 |
| `GET /api/admin/submissions/:id` | 读取允许查看的提交快照，不能串联读取私人草稿 |

推荐区分错误：未登录、无权限、无记录、版本冲突、活动关闭、限流、模型超时、模型输出无效、数据库不可用。前端提示应能帮助用户继续操作，不展示密钥、原始堆栈或他人记录是否存在等不必要信息。

## 10. 实现顺序与部署要求

### 第一步：核查与数据基础

确认现有结构，建立画像 Schema、访客身份、活动与提交数据，完成所有者过滤和数据迁移方案。持久数据结构变更采用可追踪迁移，不删除已有业务记录。

### 第二步：最小可用路径

先跑通“活动链接 → 输入 → 保存草稿 → 预览 → 提交 → 管理员查看”。此阶段可以用明确标注的本地测试数据验证接口，但最终验收必须使用真实数据库与实际请求，不以静态数组模拟多用户存储。

### 第三步：AI 与轻量交互

接入结构化提取、有限追问、初步结果、资料摘要和异常降级。将访客和管理员侧串起来验证。

### 第四步：接入既有模块

让方向探索、岗位匹配、JD 分析、求职冲刺读取统一画像。保留现有手动输入入口；修复旧版随机评分，接入同一评分服务。

### 第五步：迁移、验证与发布准备

完成旧本地数据导入、手机端状态、实际浏览器验证和启动说明。沿用当前部署方式；生产数据库必须持久保存，不能使用进程内数组或会随重启丢失的临时文件作为正式存储。

环境变量命名以现有项目为准。若需要新增，至少覆盖数据库连接、模型密钥/地址/模型名、会话配置、管理员初始化、公开访问地址和保存期限；在 `.env.example` 中只放占位符。

提供管理员初始化命令，避免提交默认凭据。模型密钥、数据库密码和账号密码不得写入仓库。

在已有部署授权和必要环境可用时完成部署与外部访问验证。缺少密钥、数据库或部署访问时，完成其余实现并具体列出阻塞项、配置位置与启动方式，不声称网站已经上线。新增付费资源、替换线上数据等操作按项目既有授权处理。

## 11. 验收标准

至少完成以下验收。对权限、数据一致性、评分等实质风险编写必要的自动化测试；页面文案和简单样式不需要堆叠重复测试。

| 编号 | 场景 | 通过条件 |
|---|---|---|
| A01 | 无经历学生 | 输入“大一，能源专业，没有项目和实习，不知道做什么”后能得到探索结果；不虚构技能和经历 |
| A02 | 已有简历 | 提取已经提供的学历、专业、经历；后续模块自动带入，不重复要求填同一内容 |
| A03 | 两次追问 | 正常回答、跳过、直接看建议、刷新、重试均不能绕过两次上限；跳过字段不被重问 |
| A04 | 提取确认 | “会一点 Python”保持原强度；用户确认后保留来源；修改某项不会确认隐藏字段 |
| A05 | 先看结果 | 不需要审核整张画像或填写联系方式即可获得初步结果；未知项可保留 |
| A06 | 统一画像 | 修改关键资料后各模块读取一致；旧分析显式过期，不冒充使用了最新资料 |
| A07 | 两个访客隔离 | 用不同浏览器/独立 Cookie 的 A、B 测试；B 更换 A 的画像/任务/提交 ID 仍不能读、写或删除 A 数据 |
| A08 | 草稿与提交隔离 | 管理员 API 和 UI 均看不到未提交正文；提交后只看到预览范围内的快照 |
| A09 | 快照与幂等 | 提交后改资料不改旧快照；双击、超时重试只产生一条记录；活动关闭后仍可取回已成功提交的回执；同幂等键不同内容被拒绝；首次提交前共享元数据变化须重新预览 |
| A10 | 异步旧结果 | AI 运行时用户修改输入；晚到结果不能覆盖新状态，也不能与新资料混合提交 |
| A11 | 活动状态与范围 | 关闭活动后新提交失败但输入不丢失；公开活动链接不返回学生记录；管理员不能读无权限活动 |
| A12 | 旧数据导入 | 未确认导入前不上传；未知键、密钥、旧分数被排除；重复导入不复制经历 |
| A13 | 撤回与删除 | 撤回后所有历史版本及旧详情地址均不能读正文，不回退显示旧版；删除后云内容与会话清理，晚到写入不能恢复数据 |
| A14 | AI 异常 | 模拟超时、限流和无效 JSON；输入保留，可重试或进入明确的规则降级；正常模型路径另外实测 |
| A15 | 评分一致 | 同一规范化画像与 JD 在新旧入口重复计算结果一致；无有效证据时不随机补分 |
