# 部署、备份与验收

## 本地

README中的Docker Compose只在127.0.0.1:55432开放PostgreSQL，数据保存在命名卷career_pg。`docker compose stop`保留数据；不要使用`down -v`删除真实数据。当前机器已生成仅本地使用的.env数据库随机密码，Git忽略该文件。

## Render预发布

1. 准备持久化PostgreSQL与数据库备份能力。不能把数据库建在Web实例的临时文件目录。
2. 选择本次代码的预发布分支或提交，先部署预发布服务，保持现有线上版本可回滚。
3. 配置DATABASE_URL、APP_ORIGIN（精确HTTPS站点，无结尾斜杠）、NODE_ENV=production、TRUST_PROXY=true。数据库TLS按供应商要求配置；DATABASE_SSL=true启用证书验证，必要时提供NODE_EXTRA_CA_CERTS，不关闭证书验证。
4. 配置DeepSeek的LLM_API_URL、LLM_API_KEY、LLM_MODEL。搜索与正文读取默认复用LLM_API_KEY，无需Coze；如单独管理搜索密钥，可配置DEEPSEEK_SEARCH_API_KEY。设置DEEPSEEK_SEARCH_ENABLED=false可关闭搜索；搜索/正文读取单独计费。
5. 构建使用pnpm install --frozen-lockfile --prod=false && pnpm build；启动前运行pnpm db:migrate，再pnpm start；健康检查/api/health。
6. 验证Cookie通过HTTPS设置、数据库迁移成功、注册登录、资料保存/恢复、用户隔离和模型真实调用。
7. 手动发布，记录部署提交与配置名称。当前render.yaml关闭自动部署，避免本次数据库改动未经验收就覆盖线上；已有服务需在控制台核对实际配置，修改仓库文件不保证已有服务设置立即改变。

NODE_VERSION使用22系列受支持的补丁版本。托管平台端口使用PORT。生产通过环境变量配置密钥，不需要上传.env。

## 数据备份与恢复

- 在数据库管理端启用自动备份和访问控制，记录保留期限、负责人及恢复步骤。
- 维护机使用 `pg_dump --format=custom --file=career.dump "$DATABASE_URL"` 生成完整备份，命令执行前确保终端环境已配置变量，不把连接信息粘进共享文档。
- 将备份保存到受控位置，不加入Git。恢复前创建独立验证数据库，用 `pg_restore --no-owner --dbname="$RESTORE_DATABASE_URL" career.dump`，检查账号数、报告和消息关系，再安排正式恢复。
- 恢复会还原个人资料与会话令牌，备份应按个人数据保护；灾难恢复后可撤销所有sessions要求重新登录。
- 迁移包含新增表与完整性约束；执行前备份并在预发布验证，遇到无效历史数据应先诊断。回滚Web代码前保留数据库备份，勿直接删除表；旧版本无法使用新账号数据，应先用预发布演练。

## 真实AI评估建议

固定10个经历、10个问答、10个JD样例，覆盖不同专业、空缺信息、矛盾门槛和恶意指令。逐例记录原始输入、预期证据、实际结果、引用支持程度、耗时和用量。关键经历/招聘事实无依据编造为发布阻断项；结构化成功率目标≥95%，返回证据可回溯和引用ID合法率目标100%。试用时评估用户是否理解“覆盖率不是录用概率”。

## 运维限制

目前没有邮件验证、密码找回与管理员后台；不要承诺长期账号恢复服务。模型请求限流和日额度为成本保护，不是供应商账单上限；同时在供应商控制台设置费用预算。注册及搜索限制为单进程内存计数，AI日额度保存在PostgreSQL，多实例部署前仍需统一入口限流和任务调度。

仓库已提供 `tests/ai-evaluation.json` 的30个合成样例（10经历、10问答、10JD）和 `pnpm evaluate:ai`。该命令会实际调用模型30次并可能产生费用，结果写入被Git忽略的artifacts/。自动结果只统计结构与原文校验，不把它冒充语义正确率，仍需逐项人工复核。
